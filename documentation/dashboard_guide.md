# Dashboard guide

Dashboards live in `dashboard/grafana/dashboards/*.json`, are generated by `infrastructure/scripts/build_dashboards.py`, and are loaded
automatically (folder **FinTech Research**; home dashboard = Overview). Data sources (UIDs): `prometheus`, `loki`, `postgres`.

| File | Dashboard | Key questions answered | Main sources |
|---|---|---|---|
| fintech_overview.json | Research Overview | Is the pipeline ready? How good is the champion? What is trust right now? | Prometheus, Loki |
| fraud_detection.json | Transaction & Fraud Analytics | When/where/how does fraud occur? What do we catch live? | Prometheus, PostgreSQL |
| cybersecurity_monitoring.json | Cyber Threat Monitoring | Which attacks, from where, how many blocked, what does the anomaly detector flag? | Prometheus, PostgreSQL, Loki |
| consumer_trust.json | Consumer Trust Indicators | CTS/PSI/CTI, dimensions, segments, drivers, scale reliability | Prometheus, PostgreSQL |
| model_performance.json | ML Model Performance | All metrics per model, confusion cells, FPR, latency | Prometheus, PostgreSQL |
| pipeline_monitoring.json | Data Pipeline Monitoring | Stage timing/status, validation, row accounting, DB writes, logs | Prometheus, PostgreSQL, Loki |
| system_performance.json | Docker Infrastructure Health | Targets up, container CPU/mem/net/disk, Prometheus & Loki internals | Prometheus (cAdvisor) |

## Metric reference (exported by `src/metrics/exporter.py`)
| Family | Examples | Updated |
|---|---|---|
| `fintech_pipeline_*` | `stage_duration_seconds{stage}`, `stage_success`, `runs_total{status}`, `ready` | each run |
| `fintech_data_*` | `validation_check_passed{check}`, `validation_pass_rate`, `cleaning_rows{kind}` | each run |
| `fintech_txn_*` | `dataset_fraud_rate`, `fraud_rate_by_category`, `fraud_rate_by_hour`, `frauds_by_pattern` | each run |
| `fintech_security_*` | `dataset_events{event_type,severity}`, `block_rate`, `anomaly_roc_auc` | each run |
| `fintech_model_*` | `metric{model,metric}`, `confusion{model,cell}`, `training_seconds`, `inference_seconds` (histogram) | run / live |
| `fintech_trust_*` | `score_mean`, `dimension_mean`, `consumer_trust_index`, `platform_security_index`, `cronbach_alpha` | each run |
| `fintech_stream_*` | `transactions_total`, `outcomes_total{outcome}`, `risk_tier_total`, `security_events_total` | every 5 s |

Live precision/recall panels are PromQL ratios over `fintech_stream_outcomes_total` (e.g. `tp / (tp + fp)` over `$__range`).

## Alerts
Grafana: *Alerting → Alert rules → FinTech Research* (live recall < 50 %, fraud rate > 6 %, pipeline stage failed, anomaly surge, trust index < 50).
Prometheus: http://localhost:9090/alerts (worker down, stage failed, validation failing, DB write failures, target down, high memory).
No contact points are configured (add one in Grafana to receive notifications).

## Editing
Change panels in the UI to explore (provisioned dashboards are editable but resets on restart unless exported), or edit the generator script and
run `make dashboards`; Grafana re-reads files every 30 s.

## Demonstrating in a viva (suggested 5-minute path)
1. Overview → readiness & indices. 2. Pipeline Monitoring → stage timings, validation failures (injected defects are visible).
3. Fraud → live outcome counters while explaining precision/recall. 4. Model Performance → FPR trade-off. 5. Trust → dimensions, α, drivers.
6. Infrastructure → containers. 7. Loki log panel → show a structured log line from the run.
